# 薪酬测算微信小程序开发与发布工作流

个人主体免费版

版本 1.0　编制日期 2026年11月5日

## 01 项目方案和执行顺序

本方案用于将当前 Flutter 薪酬测算应用实现为微信小程序，并指导个人开发者完成账号准备、备案、开发、验收和发布。首版采用个人主体，免费使用，无需用户登录，薪资参数和历史结果保存在用户设备本地。

推荐使用微信原生小程序技术栈：TypeScript、WXML、WXSS。保留现有计算口径，重写界面和平台功能。Flutter 官方支持的平台未包含微信小程序；个人小程序也不支持 web-view 组件，因此不采用将 Flutter Web 放进网页容器的发布路线。[S15][S4][S5]

### 首版产品边界

- 保留固定月薪、完整12个月、同一单位的薪酬估算；支持独立公积金基数、逐月拆解、本地历史和图片导出。
- 首页明确标注“示例参数”和“薪酬估算”。现有固定社保费率及每月3元大病统筹为演示假设，不能描述为全国统一标准。
- “税后工资”与“综合权益估算”分开展示；公积金、医保和养老账户权益不能宣传为全部可自由支取的现金。
- 首版不包含支付、广告、云同步、工资代发、报税、社保代缴、招聘、在线咨询和用户内容社区。
- 不接入自建业务服务器；小程序首次打开及代码包更新仍依赖微信网络环境，不能承诺任何情况下完全离线可启动。

### 两条工作线并行推进

| 工作线 | 执行顺序 | 汇合条件 |
| --- | --- | --- |
| 账号与资质 | 注册个人账号 → 核实类目及认证要求 → 提交备案 → 短信核验 → 获得备案号 | 后台允许提审和发布 |
| 产品与研发 | 冻结范围 → 移植算法 → 实现页面和存储 → 适配分享和隐私 → 真机验收 | 发布验收清单全部通过 |
| 正式上线 | 上传版本 → 设置体验版 → 提交代码审核 → 审核通过 → 管理员发布 → 线上复测 | 普通用户可访问且核心功能正确 |

研发可以在备案等待期间进行。备案通过、微信认证或主体核验、代码审核是不同事项，分别检查状态；任何一个通过都不能代替其余环节。[S2][S3][S16]

本项目建议优先按“工具—计算器”申报。微信当前公开类目表将该类目开放给个人主体，未列额外行业资质；薪酬估算与该类目的适配属于本方案判断，最终仍以账号后台可选范围和微信审核结论为准。[S1]

### 建议页面结构

一级导航为“测算”“历史”“说明”。测算页进入参数设置及月度详情；历史页进入快照详情；说明页包含算法、政策摘要、隐私、版本和联系信息。图片预览从当前测算与历史详情分别进入。

首版不要求新增用户账号系统。小程序内的历史只属于当前设备环境，不会自动读取 Flutter App 的 Shared Preferences，也不会跨手机同步。若未来需要数据导入，应另做导出格式、迁移校验和明确的用户操作流程。

### 可以复用和需要重写的内容

可复用的是业务规则、参数定义、税率表、公式说明、测试样例及合法拥有的图标素材。Flutter Widget、Riverpod、Shared Preferences、Screenshot、Share Plus、Gal、url_launcher 的运行时代码不能直接放入微信小程序，应替换为对应页面、状态、存储和微信 API。[S4]

## 03 技术设计和数据约定

建议在仓库新增独立的 `miniprogram/` 项目，继续保留 Android 和 iOS 工程。小程序使用微信开发者工具创建 TypeScript 工程，并选定稳定基础库版本；正式兼容范围以真机验证结果为准。[S4]

### 推荐目录职责

| 目录 | 内容 |
| --- | --- |
| `miniprogram/pages/` | 测算、参数、历史、详情、说明、隐私和图片预览 |
| `miniprogram/components/` | 方案卡片、金额项、月度列表、费率说明 |
| `miniprogram/domain/` | 输入模型、纯计算引擎、金额格式化和规则版本 |
| `miniprogram/repositories/` | 本地参数、历史列表、读写及版本迁移 |
| `miniprogram/services/` | 图片绘制、分享、隐私授权和内容读取 |
| `miniprogram/content/` | 算法、政策摘要、来源和隐私说明 |
| `miniprogram/tests/` | Dart 基准数据、计算对照和存储回读测试 |

数据流为：输入 → 校验 → 整数金额模型 → 计算引擎 → 结果展示。用户点击保存后生成快照；用户点击分享后根据当前结果或历史快照生成图片。页面不自行复制税费公式。

### 金额精度与版本

金额用整数“分”，比例用整数基点，100基点等于1%。现有正数比例计算为 `floor((amountCents * rateBps + 5000) / 10000)`，按分四舍五入。先按项目逐项舍入，再做月度及年度求和，不能在年度汇总时重新套比例。

现有输入上限为 99,999,999,999 分。移植时应检查全部中间乘积、累计金额和求和仍为 JavaScript 安全整数；不能用位运算截断金额。金额字符串按整数和两位小数解析，不用浮点乘100代替输入解析。

参数保留 `schemaVersion`，规则使用 `rulesVersion`。历史快照包含ID、保存时间、输入参数、规则版本、年度汇总和12个月明细。打开历史时读取已保存结果，不能用新版规则静默覆盖。参数与历史使用独立存储键，历史采用列表索引加单条快照分键存储，避免把全部记录放入一个键。

### 存储可靠性

使用 `wx.getStorage`、`wx.setStorage` 等本地存储接口并处理失败。历史条数上限建议设为100条，这是产品约束，不是微信容量上限；还需检查单键1MB及总计10MB的接口限制。达到上限时提示用户删除；写入失败时保留当前页面结果，不能假报“保存成功”。损坏记录应提示异常且保留其他有效记录；清空数据需要二次确认。微信缓存可能被清理，说明中提示用户重要结果另行导出。[S9]

## 04 研发任务与交付工作流

下列角色可由同一个人承担。每项任务只有达到完成标准才进入下一阶段，账号备案线同时推进。

| 阶段 | 具体任务 | 交付物和完成标准 |
| --- | --- | --- |
| D1 需求冻结 | 确认免费范围、页面、示例费率及名称；记录工作区基线 | 功能清单、页面草图、输入输出表 |
| D2 工程建立 | 新建小程序项目，设置 AppID、目录、构建和版本管理 | 微信开发者工具及手机可打开首页 |
| D3 算法迁移 | 将 Dart 模型、累计预扣逻辑、舍入和格式化迁到 TypeScript | 默认、税档边界、极值样例逐字段一致 |
| D4 主流程 | 实现首页、设置、结果、月度拆解、存储和历史 | 完成编辑 → 计算 → 保存 → 重开 → 查看 |
| D5 平台适配 | 实现 Canvas 图片、分享、规则页、隐私及联系入口 | 分享成功、取消和拒绝授权均可继续计算 |
| D6 发布验收 | 真机测试、配置校验、材料整理和上传 | 验收记录、体验版、版本说明和提审材料 |

### 算法迁移顺序

先锁定现有输入结构及完整输出字段，再用 Dart 导出基准 JSON；随后移植 TypeScript 引擎并比较每个月、每个字段以及年度汇总。最后接入页面。测试样例和预期值需要在计算引擎之外维护，不能从待测函数本身生成预期结果。

### 已确认的兼容问题

当前工资为0时，固定3元大病统筹仍扣除，月税后工资为负3元，年税后工资为负36元；现有快照读取函数拒绝负金额，导致这类记录无法正常回读。小程序方案保留计算结果并提示“扣款超过工资，请核对参数”，允许净现金和综合权益结果字段为负，其他依法应非负的金额字段继续校验。迁移时为该规则升级存储版本，并增加保存后回读测试。

当前算法还将每月应税收入增量最低置为0。这与固定月薪的首版范围一致；如果后续支持年中调薪、奖金或入离职，必须重新设计累计逻辑和测试，不能只增加输入框。

### 开发交付纪律

每次交付附带改动范围、测试结果和剩余问题。AppSecret、上传私钥等凭证不进入前端包或仓库；本地计算首版本身不需要在客户端保存这些凭证。发布前保留一个可复现版本及版本号，确保问题发生时能定位到代码和规则版本。

### 本路线无需预先购买的项目

不需要为这个纯本地首版专门购置服务器、域名、云数据库或支付商户号。普通计算器类目未将软件著作权列为普遍必交资质；如果遇到名称权利证明、版权争议或后台额外核验，则按实际要求补充。[S1]

### 四种要求分别看

注册及主体核验确认“由谁运营”；微信认证是平台的认证流程；小程序备案是主管部门的登记；代码审核检查版本内容和功能。不要将认证费称为备案费，也不要将备案号当作经营许可证。[S2][S16][S7]

以后增加付费、广告、咨询、代办或平台业务时，应重新核对主体、类目、接口和经营要求。当前个人免费版获准上线，不能推导为这些后续能力也可直接开通。

## 07 账号申请与备案操作流程

### 第一步 注册并确认发布范围

进入微信公众平台，选择注册“小程序”，按页面激活邮箱，主体选择“个人”，填写本人信息并绑定管理员微信。登记 AppID，添加实际开发成员；只有需要内测的人员加入体验成员。[S6][S11]

登录后台后，先核实“工具—计算器”是否可选，再完善名称、头像和简介。名称避免暗示税务、社保等官方身份；可暂拟“薪酬测算助手”，最终以名称可用性和审核为准。查看发布任务及认证入口，按当前个人账号要求完成认证，记录费用和有效期。

### 第二步 尽早提交小程序备案

从首页“去备案”或设置中的“小程序备案”入口进入。已有主体备案信息的，依页面选择对应新增或接入流程；首次备案的，选择新增备案。填写真实主体、负责人、地址、服务内容及小程序信息，上传证件并完成人脸核验、承诺书确认。[S2]

小程序信息与账号、名称、管理员和实际功能应一致。前置审批材料按真实业务和页面要求提交，不应为了缩短流程选择与实际内容不符的业务类型。纯本地架构也需要完成小程序备案；没有自建服务器不等于免备案。[S2][S7]

### 第三步 平台初审和短信核验

微信公开指引给出的平台初审参考为1至2个工作日。初审期间保持电话畅通，按通知补正资料。初审通过后，留意12381发来的核验短信；收到后需在24小时内到工信部备案系统完成短信核验，超时可能自动退回，需要重新提交。[S2][S3]

### 第四步 通信管理局审核

短信核验成功后进入属地通信管理局审核。工信部规定，材料齐全准确的，收到后应在20个工作日内予以备案。这个期限不是从开始注册起算，也不包含全部补正和平台初审时间。微信指引列出的参考范围为1至20个工作日。[S2][S7]

### 第五步 核验备案结果

获批后记录真实备案号，核对主体和小程序信息。微信指引说明，小程序发布后备案号会自动展示于“更多资料”页，无需开发者自行悬挂；上线复测时应检查可见性。产品“关于”页可补充备案查询说明，不能编造或复用其他小程序的备案号。[S2]

本项目不单独办理自建网站域名备案。若未来增加境内网站或业务后端，再按部署方式核对域名、接入备案、HTTPS及合法域名配置；这些事项不能用现有小程序备案直接替代。

## 08 隐私与分享功能工作流

### 数据处理约定

工资、专项扣除、缴费基数、比例和历史结果只在本地计算、保存。首版不获取用户手机号、头像、昵称、位置、身份证、通讯录，不添加第三方分析或广告 SDK。政策内容随代码包发布；规则更新通过版本发布，不在后台偷偷改变算法。

在说明页提供“数据与隐私”入口，写清处理的数据、用途、保存位置、删除方式和联系渠道。薪资在本地处理仍应透明说明，不能因无服务器就写“完全不处理任何数据”。微信平台自身的基础处理按其规则进行，不应承诺微信也不处理任何信息。

后台《小程序用户隐私保护指引》需要与代码所用接口逐项一致。涉及微信隐私接口时，先按官方机制取得并同步用户同意，再调用；操作系统相册权限与隐私同意分别处理。拒绝导出相关授权时，只停止该导出操作，保留计算和历史查看。[S8]

### 分享分为两个入口

1. 分享小程序入口：分享标题和封面使用通用内容；路径只到首页，不附加工资、扣除、历史ID或其他私人参数。接收者看到自己的本地状态或示例，不会继承发送者工资。
2. 分享本次结果：用户主动点击后，根据当前结果或历史快照用 Canvas 生成图片，先预览再分享。图片包含参数、年度及月度结果、规则版本、生成时间和“估算”说明；明确提示图片含薪资信息。

图片通过 `wx.canvasToTempFilePath` 转成本地临时文件，优先调用 `wx.showShareImageMenu`。该接口提供微信图片分享弹窗，不能用 Flutter 的系统分享插件替代。显式设置通用入口路径或关闭附带入口，避免沿用带私人参数的当前页面路径。[S10][S12]

需要保存到相册时，在用户主动点击后调用 `wx.saveImageToPhotosAlbum`，按接口要求处理隐私和相册授权。接口不支持、被拒绝或发生错误时，保留预览并提示可用操作；不把“取消”写成“发送成功”。长图失败时可降级为摘要图和月度明细分图。[S10][S13]

### 政策来源呈现

个人小程序当前不支持 web-view。规则页面展示本地摘要、发布机构、文件名称、适用时间与官方来源，提供复制来源网址的辅助入口；不把外部链接设置成计算或提审的必经步骤。[S5]

上线前由维护者核对政策说明的有效性与适用地区。文档中的算法基准验证只确认代码一致性，不代替费率和税务规则核验。

## 09 提审发布及退回处理

### 提审前准备

准备名称、头像、简介、真实服务类目、隐私保护指引、联系渠道、页面截图、版本号和更新说明。确认备案及账号认证任务状态正常，代码中没有测试凭证、空页面或尚未实现的功能入口。首版无登录功能，不需要为审核员编造测试账号。

建议简介为：“提供固定月薪条件下的工资、社保、公积金和年度个税估算，支持逐月拆解与本地历史记录。结果仅供参考。”避免使用“官方”“全国精准”“保证到账”等描述。

### 从体验版到正式版

1. 开发者在微信开发者工具选择正式 AppID，检查构建配置并上传代码，填写版本号及说明。
2. 在后台版本管理中将对应开发版本设置为体验版，添加体验人员，完成iOS和Android真机验收。
3. 核对本次提交的版本，填写功能页面和审核说明，提交代码审核。
4. 等待审核结果。被退回时保留反馈及复现路径，针对问题修复，重新测试并上传新版本。
5. 审核通过后，由管理员在后台执行发布。审核通过不等于自动上线；如使用自动发布设置，需提前确认其行为。
6. 使用普通微信用户从小程序入口访问，检查版本、计算、存储、分享、隐私及备案信息，并保存发布记录。[S6]

### 可复制的审核说明

本小程序提供固定月薪、完整12个月条件下的薪酬估算。使用者无需注册或登录，可在首页进入参数设置，填写工资、专项附加扣除及缴费参数，返回查看年度及逐月结果；可保存本地历史并主动生成结果图片。数据保存在本机。当前版本免费，无支付、广告、社保代缴、工资代发和报税服务。默认参数为演示方案，结果为估算值，适用范围和计算说明可在“说明”页查看。

### 常见退回的处理方法

| 反馈类型 | 处理动作 |
| --- | --- |
| 类目或简介不符 | 对照实际页面修正类目、功能或描述，再提交 |
| 隐私声明不一致 | 核对接口清单、同意流程及后台声明，重新真机验证 |
| 功能无法体验 | 修复空状态、导航、授权拒绝和首次启动流程 |
| 专业内容误导 | 明确示例费率、适用范围、来源和估算口径 |

如线上出现重大计算或隐私问题，先依据后台可用能力暂停服务或回退，再修复并重新提审；首次发布没有历史正式版可回退。不要把“后台一定可秒回滚”作为上线保障。

定期核对政策来源、认证有效期、负责人和联系方式；名称、主体或负责人等备案信息变化时按要求办理变更，停止运营时按要求办理注销。新增后端、收费、广告或其他业务之前，重新评估类目和隐私，不直接沿用首版结论。[S2][S3]
