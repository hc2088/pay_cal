# 薪酬测算 Flutter 研发实现文档

## 1. 文档信息

- 文档类型：研发实现文档
- 对应产品文档：[薪酬测算Flutter产品设计文档.md](薪酬测算Flutter产品设计文档.md)
- 计算依据：[薪酬计算.md](薪酬计算.md)
- 技术：Flutter / Dart
- 最低工具链：Flutter 3.38 / Dart 3.10；Android 使用 Gradle 8.14、AGP 8.11.1、Kotlin 2.2.20
- 目标平台：Android、iOS
- 版本范围：固定月薪计算器 MVP

## 2. 研发目标

交付一个离线薪酬计算器：内置默认参数，支持编辑月工资、专项附加扣除、社保基数和公积金比例；按累计预扣法计算 12 个月个税；展示单位成本、税后现金、权益 A 和权益 B。

计算核心必须与 Flutter UI 解耦，使用定点金额运算，结果能从输入参数和规则版本重新计算。首版不接服务端，不实现账号、多方案或地区费率管理。

## 3. 依赖与架构

### 3.1 建议依赖

| 用途 | 建议方案 |
|---|---|
| Flutter 状态管理 | Riverpod |
| 本地设置 | SharedPreferences，保存带 schemaVersion 的 JSON |
| 日期与本地化格式 | intl；金额运算不依赖 intl |
| 金额运算 | 整数分 + 整数基点；不使用 double 计算最终金额 |
| 路由 | 单页 MVP 暂不需要路由库 |

依赖保持精简。计算税表、费率、结果模型和格式逻辑使用 Dart 标准类型实现。

### 3.2 分层

| 层 | 职责 | 建议目录 |
|---|---|---|
| 应用层 | 主题、启动、Provider 初始化 | lib/app/ |
| 计算领域层 | Money、Rate、默认参数、税表、计算引擎、结果模型 | lib/calculation/ |
| 功能界面层 | 参数表单、四项指标、月度明细、计算依据 | lib/features/calculator/ |
| 数据层 | 参数序列化、本地读取与保存 | lib/data/ |
| 通用组件 | 金额输入、指标卡、提示组件 | lib/core/widgets/ |

依赖方向为：界面层调用领域层，数据层只负责配置的读写。领域层不得导入 Flutter、Widget 或本地存储库。

### 3.3 数据流

1. App 启动时读取本地 CalculatorInputs；读取失败或无数据时加载默认值。
2. 输入组件维护字符串草稿，字段可编辑中间态不会直接写入计算模型。
3. 字段解析成功后生成新的 CalculatorInputs。
4. Provider 调用纯函数 CalculationEngine.calculate(inputs)。
5. 结果模型刷新 UI，同时异步保存有效输入。
6. 输入无效时显示字段提示，并标记结果不可代表当前编辑草稿；不得让用户误以为旧结果对应未提交的新输入。

## 4. 数值约定

### 4.1 Money 与 Rate

- 金额内部单位为人民币分，类型为整数。
- 费率内部使用基点：100% = 10,000；12% = 1,200；0.5% = 50。
- 税档速算扣除数以分存储。
- 页面显示人民币两位小数；输入时允许最多两位小数。
- 费率输入显示百分号，保存前转换为基点。

比例计算对非负金额使用分级四舍五入到分：计算“金额分 × 基点 / 10,000”时，分子加 5,000 后整除 10,000。金额输入范围需受控，避免乘法溢出；首版可设置合理上限并在 UI 提示。

### 4.2 舍入顺序

1. 每项单位/个人缴费先独立舍入到分。
2. 扣款与应税收入使用已舍入到分的缴费额计算。
3. 累计税额计算后舍入到分。
4. 当月预扣税 = max(0，当前累计应纳税额 - 本年此前已预缴税额)。
5. 当月应税额为 0 时，本月累计应纳税所得额不增加。

月度金额先舍入、全年按月度值求和。演示资料存在逐月舍入造成 0.01 元差异，回归允许最多 0.01 元误差；33,000 元默认方案要求与演示值精确到分。

默认输入：

| 字段 | 值 |
|---|---:|
| 月税前工资 | 3,300,000 分 |
| 月专项附加扣除 | 500,000 分 |
| 社保基数模式 | 跟随工资 |
| 自定义社保基数 | 空；仅 custom 模式使用 |
| 公积金比例 | 1,200 基点 |
| 基本减除费用 | 500,000 分/月 |
| 个人大病统筹 | 300 分/月 |

固定费率：

| 缴费项 | 单位基点 | 个人基点 |
|---|---:|---:|
| 养老保险 | 1,600 | 800 |
| 医疗保险 | 980 | 200 |
| 失业保险 | 50 | 50 |
| 工伤保险 | 50 | 0 |
| 住房公积金 | 用户比例 | 用户比例 |

社保统一使用社保基数 S。公积金基数首版固定跟随税前工资 A。费率和税表集中放在版本化的 TaxAndContributionRules 配置中，计算结果记录 rulesVersion。

## 6. 数据模型

建议按不可变模型实现，修改输入时创建新对象。

### 6.1 CalculatorInputs

| 字段 | 类型 / 说明 |
|---|---|
| grossMonthlySalaryCents | int，税前工资 |
| specialAdditionalDeductionCents | int，月专项附加扣除 |
| socialBaseMode | enum，followSalary 或 custom |
| customSocialBaseCents | int?，自定义社保基数 |

基本减除费用、大病统筹、固定费率和税表不放入用户输入；由规则配置提供。

### 6.2 MonthlyCalculationResult

| 字段 | 说明 |
|---|---|
| month | 月份 1–12 |
| salaryCents / socialBaseCents | 本月工资与社保基数 |
| employerPensionCents 等 | 单位各险种和公积金金额 |
| employeePensionCents 等 | 个人各险种、公积金和大病扣款 |
| personalDeductionTotalCents | 个人扣款总额 |
| taxableIncomeIncrementCents | 当月新增应纳税所得额 |
| cumulativeTaxableIncomeCents | 累计应纳税所得额 |
| taxBracketRateBps / quickDeductionCents | 本月对应税档参数 |
| cumulativeTaxDueCents / monthlyTaxCents | 累计应纳税额与当月预扣税 |
| netCashCents | 当月税后现金 |
| benefitACents / benefitBCents | 当月权益 A、权益 B |
| employerTotalCostCents | 单位月成本 |

### 6.3 CalculationResult

保存本次输入快照、rulesVersion、12 项 MonthlyCalculationResult，以及各指标年度合计。结果可从快照重算；不需要将派生结果持久化。

## 7. 计算引擎契约

入口建议为纯函数：

CalculationResult calculate(CalculatorInputs inputs, TaxAndContributionRules rules)

对于 MVP，工资和专项扣除全年固定，生成 12 个相同输入月份；税额状态按月份累计。

### 7.1 每月缴费计算

令 A 为月税前工资，S 为本月社保基数，r 为公积金基点比例：

- 单位养老 = S × 16%；单位医疗 = S × 9.8%；单位失业 = S × 0.5%；单位工伤 = S × 0.5%。
- 个人养老 = S × 8%；个人医疗 = S × 2%；个人失业 = S × 0.5%。
- 单位公积金 = A × r；个人公积金 = A × r。
- 单位成本 = A + 单位各项社保 + 单位公积金。
- 个人扣款总额 = 个人各项社保 + 个人公积金 + 3 元。

### 7.2 应税收入和累计税

- 当月新增应纳税所得额 = max(0，A - 个人扣款总额 - 5,000 元基本减除费用 - 专项附加扣除)。
- 本月累计应纳税所得额 = 上月累计应纳税所得额 + 当月新增应纳税所得额。
- 按累计应纳税所得额查找唯一税档。
- 累计应纳税额 = max(0，累计应纳税所得额 × 该档税率 - 该档速算扣除数)。
- 当月预扣税 = max(0，累计应纳税额 - 本年此前已预缴税额)。
- 税后现金 = A - 个人扣款总额 - 当月预扣税。

税档边界按累计金额确定：不超过 36,000 元为 3%；36,000–144,000 元为 10%；144,000–300,000 元为 20%；300,000–420,000 元为 25%；420,000–660,000 元为 30%；660,000–960,000 元为 35%；超过 960,000 元为 45%。边界金额归入低档。

| 累计应税收入上限 | 税率 | 速算扣除数 |
|---:|---:|---:|
| 36,000 元 | 3% | 0 元 |
| 144,000 元 | 10% | 2,520 元 |
| 300,000 元 | 20% | 16,920 元 |
| 420,000 元 | 25% | 31,920 元 |
| 660,000 元 | 30% | 52,920 元 |
| 960,000 元 | 35% | 85,920 元 |
| 无上限 | 45% | 181,920 元 |

### 7.3 权益及年度汇总

- 权益 A = 税后现金 + 单位公积金 + 个人公积金 + 个人医疗缴费金额。
- 权益 B = 权益 A + 个人养老缴费金额。
- 单位成本、税后现金、权益 A、权益 B 的全年值，分别为 12 个月对应结果相加。
- 失业保险和大病统筹不计入权益；工伤由单位缴纳，不计入个人权益。

### 7.4 33,000 元回归基准

输入：工资 33,000 元、社保基数 33,000 元、专项附加扣除 5,000 元、公积金比例 12%。

必须得到：

| 验证项 | 预期 |
|---|---:|
| 单位社保 / 月 | 8,844.00 元 |
| 单位公积金 / 月 | 3,960.00 元 |
| 单位成本 / 月 | 45,804.00 元 |
| 个人社保 / 月 | 3,465.00 元 |
| 个人公积金 / 月 | 3,960.00 元 |
| 个人扣款合计 / 月 | 7,428.00 元 |
| 当月新增应税收入 | 15,572.00 元 |
| 全年个税 | 20,452.80 元 |
| 全年税后现金 | 286,411.20 元 |
| 全年权益 A | 389,371.20 元 |
| 全年权益 B | 421,051.20 元 |

月度税额档位应为：1–2 月 3%，3–9 月 10%，10–12 月 20%。预扣税分别见 [产品设计文档的默认演示表](薪酬测算Flutter产品设计文档.md#64-33000-元默认方案的演示基准)。

**口径保护：**《薪酬计算.md》中 33,000 元对应的 25,572 元是工资扣除个人缴费后的计税前余额，等于 A - 个人扣款总额；它不是个人扣款额。个人扣款额是 7,428 元。

## 8. 本地存储

- 使用单一版本化配置键存储 CalculatorInputs。
- 只存用户输入和 schemaVersion，不存计算结果。
- 加载后校验字段；未知版本或无效数据采用默认值，并避免覆盖原数据直到有效输入保存成功。
- 用户点击恢复默认时重置工资、专项扣除、公积金比例和基数模式。
- 不实现网络请求；薪酬数据不进入日志、分析事件或崩溃上报。

## 9. 状态管理与 UI 实现

推荐的状态分层：

- CalculatorSettingsController：加载、更新、恢复默认、持久化输入。
- CalculationProvider：根据有效 CalculatorInputs 派生 CalculationResult。
- 输入组件本地保存编辑草稿，提交后统一解析并校验。

输入字段需支持部分编辑状态，例如暂时清空金额。无效草稿不可触发错误计算；界面显示对应字段提示，并避免旧结果被误认为是新草稿的结果。有效输入的计算应同步完成，计算后再异步写入本地存储。

首版页面包括参数卡片、四项结果卡片、全年/月份选择、12 个月列表、计算依据展开区和测算说明。小屏两列或单列布局，所有输入控件提供语义标签。

## 10. 错误处理与输入限制

- 工资、专项附加扣除、社保基数：金额不得为负数，最多两位小数。
- 公积金比例：接受 0%–100%，最多两位小数；内部换算为基点。
- 社保基数模式为 followSalary 时忽略 customSocialBaseCents，并始终令 S = A。
- 计算模块对非法模型输入返回明确的 validation error，不静默生成负缴费或 NaN。
- 本地读取异常降级为默认配置；保存异常提示“本次结果仍可使用，但未保存设置”。
- 不存在本地网络故障状态；所有规则和计算均随 App 提供。

## 11. 测试设计

### 11.1 计算单元测试

- 17,000、20,000、30,500、33,000 元四组演示年度税额、现金、权益 A/B。
- 33,000 元逐月税档、个税和年度合计。
- 社保基数跟随工资；自定义基数低于或高于工资。
- 公积金比例变更对个人扣款、单位成本、税额及权益的影响。
- 无专项附加扣除、专项附加扣除为 0、应纳税所得额小于 0。
- 税档边界上下各一分，确保边界归档一致。
- 非法费率、负数金额、极大金额、逐月舍入和年度汇总一致性。

### 11.2 Widget 测试

- 默认值正确显示，恢复默认会清除社保基数自定义状态。
- 编辑工资或专项扣除后结果刷新。
- 编辑社保基数后从跟随模式切为自定义。
- 修改公积金比例后四项核心指标与拆解值同步。
- 全年/月度切换和月份选择正确。
- 输入无效时显示字段提示且不展示误导性旧结果。

### 11.3 集成验证

覆盖首次打开 → 修改参数 → 查看逐月结果 → 关闭重启 → 确认参数恢复 → 离线再次计算。

## 13. 完成定义

- 33,000 元默认方案达到第 7.4 节精度要求。
- 四组演示案例符合来源文档，逐月舍入差不超过 0.01 元。
- 所有用户输入从模型校验后进入计算引擎，UI 中不散落计算公式。
- 月度结果加总得到年度指标；月度税档和累计个税可追溯。
- 无效输入不会导致应用崩溃或展示貌似有效的旧结果。
- 离线启动、参数本地恢复、默认值恢复均可用。
- Android 与 iOS 内部测试包均可构建；薪酬数据不被记录到日志。

## 14. 风险与后续扩展

| 风险 | 当前处理 |
|---|---|
| 地区社保、公积金费率及上下限不同 | MVP 固定使用来源文档费率并展示假设；后续增加地区模板 |
| 税务规则年度变化 | 将税表和规则版本化；正式发布前由产品确认适用年份 |
| 源文档某列名称与数值含义不一致 | 以缴费率和逐月明细交叉校验，按第 7.4 节拆分扣款 |
| 个人医保实际入账口径因地区不同 | 首版按个人医疗缴费金额计入权益 A，并明确这是估算口径 |
| 将权益误解为可支取现金 | 将现金、权益分开展示，并标注养老、公积金的流动性差异 |

后续可按优先级增加地区模板和上下限、逐项专项附加扣除、逐月工资变化、奖金计算、多方案对比、导出和云同步。
