# 薪酬测算：算法说明

这份说明解释页面里的税前工资如何依次变成个人扣款、预扣个税、到手现金和单位成本，也演示年度速算扣除数的推导。

> **先看适用范围**：这是帮助理解工资结构的估算模型。示例按居民个人、同一单位、全年 12 个月领取固定月薪测算。社保费率和缴费基数会因地区、年度和个人情况而异；本应用中的费率是演示参数，不代表全国统一标准。计算结果不能代替工资单或税务申报。

## 一、先分清三类扣除

个人所得税不是简单地对税前工资直接乘一个税率。测算先从收入中扣除符合模型口径的个人缴费，再扣除基本减除费用和专项附加扣除，得到应纳税所得额。

| 名称 | 本应用采用的口径 | 是否全国固定 |
| --- | --- | --- |
| 基本减除费用 | 每月 5,000 元；在职 12 个月时全年 60,000 元 | 法定标准 |
| 专项附加扣除 | 输入框里的每月金额，默认示例为 5,000 元 | 否，按个人符合条件的项目填写 |
| 个人五险一金等 | 根据下表费率、社保基数和公积金比例计算；另含固定 3 元大病统筹示例值 | 否，受地区和缴费规则影响 |

页面默认的 5,000 元“专项附加扣除”只是测算输入值，不是每个人都能固定扣除的法定额度，也不等同于基本减除费用 5,000 元。实际可扣金额要按本人符合条件的项目申报，例如子女教育、赡养老人、住房租金或住房贷款利息等。

### 默认 5,000 元的示例拆分

为了说明默认输入的来源，本项目把每月 5,000 元示例拆分为：

| 示例项目 | 月金额 | 说明 |
| --- | ---: | --- |
| 子女教育 | 2,000 元 | 假设由本纳税人按 100% 扣除一个符合条件的子女 |
| 赡养老人（非独生子女） | 1,500 元 | 假设本人分摊到非独生子女扣除上限 |
| 住房租金 | 1,500 元 | 假设符合 1,500 元档的城市和租房条件 |
| **合计** | **5,000 元** | 作为本应用的默认测算值 |

这是一个按官方分项标准组成的示例情景，不是国家规定的固定组合，也不代表每位用户都满足这些扣除条件：

- **子女教育**：每个符合条件的子女每月定额扣除 2,000 元，父母可选择一方扣除 100%，或双方分别扣除 50%。示例假设本纳税人选择扣除 100%。
- **赡养老人**：非独生子女与兄弟姐妹分摊每月 3,000 元额度，每人每月最多扣除 1,500 元；示例假设本人按上限分摊。
- **住房租金**：须符合主要工作城市无自有住房等条件，按城市类别每月定额扣除 1,500 元、1,100 元或 800 元；示例按 1,500 元档计算。

当前应用只接收一个“每月专项附加扣除”合计数，不会按项目校验资格、分摊方式或城市标准。实际填报时请以本人符合的条件和税务部门申报口径为准；专项附加扣除也不要与每月 5,000 元基本减除费用混为一项。

## 二、五险一金：个人扣多少，单位付多少

本应用当前的示例费率如下。养老、医疗、失业和工伤使用页面中的“社保缴费基数”；住房公积金按单独显示的“公积金缴存基数”乘以公积金比例计算，单位和个人各缴一份。默认公积金基数跟随社保基数，也可以自定义。

| 项目 | 单位缴费 | 个人缴费 | 计算基数 |
| --- | ---: | ---: | --- |
| 养老保险 | 16% | 8% | 社保基数 |
| 医疗保险 | 9.8% | 2% | 社保基数 |
| 失业保险 | 0.5% | 0.5% | 社保基数 |
| 工伤保险 | 默认 0.2%（可自定义） | 0% | 社保基数 |
| 住房公积金 | 与个人相同 | 与单位相同 | 公积金缴存基数 H |
| 大病统筹 | — | 固定 3 元/月 | 固定示例值 |

工伤保险由单位承担，个人不缴。本应用工伤费率默认 0.2%，可在参数区修改；计算时按用户设置的社保缴费基数和该费率估算单位缴费。国家实行行业差别费率与单位浮动费率相结合的制度，0.2%与国家一类行业基准费率相同，仅作为演示默认值，并非所有单位的统一费率。个人工资里扣掉的养老、医疗、失业、公积金和大病统筹，会降低当月现金；符合规定的个人社保、公积金缴费也会作为税前专项扣除纳入个税测算。

### 用变量写出扣款公式

令：

- `S` = 税前月工资；
- `B` = 社保缴费基数；默认“跟随工资”时 `B = S`，也可以手动设置；
- `H` = 公积金缴存基数；默认跟随当前社保基数 `B`，也可以单独自定义；
- `r` = 公积金比例；默认值为 12%，单位和个人分别缴纳；
- `w` = 工伤保险费率；默认值为 0.2%，由用户按单位实际核定费率设置；
- `D` = 每月专项附加扣除输入值；默认示例为 5,000 元。

那么个人每月扣款为：

```text
个人扣款 = B × (8% + 2% + 0.5%) + H × r + 3
         = B × 10.5% + H × r + 3
```

单位每月承担的缴费为：

```text
单位缴费 = B × (16% + 9.8% + 0.5% + w) + H × r
         = B × (26.3% + w) + H × r
单位总成本 = 税前工资 S + 单位缴费
```

默认跟随工资且公积金跟随社保基数、公积金比例为 12%、工伤费率为 0.2% 时，`B = H = S`，个人扣款比例为 22.5%，单位成本比例为税前工资的 138.5%；个人另扣固定 3 元大病统筹。调整工伤费率会相应改变单位缴费和单位总成本，不影响个人扣款。若自定义社保或公积金基数，比例简式就不再直接成立，应按 `B`、`H` 和 `S` 分别计算。应用不自动套用各地缴费上下限。

住房公积金基数在实际缴存中通常按本人上一年度月平均工资核定，新参加工作或调入职工等情形另有规定；它不必与社保基数相同。本应用为便于联动测算，默认 `H = B`，但允许单独自定义。国家基数规则和 3,500 元、175 元示例的适用说明见 [住房公积金缴存基数规则](rules/housing_fund_base.md)。

### 工伤保险费率为什么可以不同

国家层面按行业工伤风险类别设置一类至八类基准费率，分别约为 0.2%、0.4%、0.7%、0.9%、1.1%、1.3%、1.6% 和 1.9%。在行业基准费率上，还会结合用人单位的工伤保险基金使用、工伤发生率等情况实行浮动费率；统筹地区也会按规定确定具体标准。因此，不同公司即使在同一地区，也可能因为行业类别和浮动档次不同而采用不同费率。

本应用把工伤费率作为可编辑参数，默认 0.2% 参照国家一类行业基准费率，仅作演示，不代表本单位应适用该费率。实际费率应以当地社保经办机构核定的本单位费率为准。本应用仍将页面的社保缴费基数作为工伤保险计算基数进行简化估算。

## 三、工资怎样变成应纳税所得额

每月先从税前工资中减掉个人缴费，再减掉基本减除费用 5,000 元和专项附加扣除输入值：

```text
当月新增应纳税所得额
= max(0, 税前工资 - 个人五险一金等扣款 - 5,000 - 专项附加扣除)
```

在默认社保基数跟随工资、公积金 12% 的示例下，个人缴费 = `22.5% × 工资 + 3`，所以：

```text
当月新增应纳税所得额
= max(0, 77.5% × 税前工资 - 5,003 - 专项附加扣除)
```

当专项附加扣除填 5,000 元时，公式进一步变成：

```text
当月新增应纳税所得额 = max(0, 77.5% × 税前工资 - 10,003)
```

这里的 `10,003` 由基本减除费用 5,000 元、示例专项附加扣除 5,000 元和固定大病统筹 3 元组成。页面按月把新增应纳税所得额累加，再用年度累计预扣率表计算个税。

## 四、累计预扣：为什么后几个月税会变多

工资薪金通常采用**累计预扣法**。到某个月时，先用截至该月的累计应纳税所得额算出累计应预扣税额，再减去本年之前已经预扣的税，得到本月税额：

```text
累计应纳税所得额
= 累计工资收入
 - 累计基本减除费用
 - 累计个人专项扣除（如符合条件的社保和公积金）
 - 累计专项附加扣除
 - 依法可扣除的其他项目

累计应预扣税额 = 累计应纳税所得额 × 对应预扣率 - 对应速算扣除数
本月应预扣税额 = 累计应预扣税额 - 本年已预扣税额
```

基本减除费用按在本单位任职受雇的月份数累计：每月 5,000 元。随着累计收入增加，累计应纳税所得额可能进入更高一档，因此年初每月税额较低、后续月份可能提高。跨档后只对超出档位边界的部分适用更高的边际税率，并不是整份工资突然都按高税率征税。

本应用的简化模型按输入的同一月薪和扣除额测算完整 12 个月；遇到入离职、工资变化、奖金、多家单位或其他扣除时，真实预扣结果需要按实际累计数据计算。

## 六、速算扣除数是怎样推出来的

税率本来是超额累进的：每一段收入按自己的税率分别计算。为了快速计算，可以把分段求和整理成一个乘减公式：

```text
分段累进税额 = 累计应纳税所得额 × 当前档税率 - 速算扣除数
```

速算扣除数是一个**补差常数**。它把“高档税率乘完整个金额”多算出来的部分减回去，所以计算结果仍等于逐档累加的税额。

### 演示：第二档 10%，速算扣除数 2,520 元

假设累计应纳税所得额为 `40,000 元`：

1. 前 `36,000 元` 在第一档，税额是 `36,000 × 3% = 1,080 元`。
2. 超过 `36,000 元` 的 `4,000 元` 在第二档，税额是 `4,000 × 10% = 400 元`。
3. 分段计算的真实税额为 `1,080 + 400 = 1,480 元`。
4. 若直接把 `40,000 元` 全乘 10%，会得到 `4,000 元`，因此要减掉多算的 `4,000 - 1,480 = 2,520 元`。

于是第二档可以直接写成：

```text
累计应预扣税额 = 累计应纳税所得额 × 10% - 2,520
40,000 × 10% - 2,520 = 1,480 元
```

### 再看第三档 20%，速算扣除数 16,920 元

累计应纳税所得额达到 `144,000 元` 时，前两档累计税额是：

```text
36,000 × 3% + (144,000 - 36,000) × 10%
= 1,080 + 10,800
= 11,880 元
```

若把 `144,000 元` 全按 20% 算，会得到 `28,800 元`。两者相差 `28,800 - 11,880 = 16,920 元`，因此第三档公式是：

```text
累计应预扣税额 = 累计应纳税所得额 × 20% - 16,920
```

其它档位用同样的方法推导：在档位下边界，先算出此前各档的分段税额，再用“边界金额 × 当前档税率”减去它，差值就是当前档的速算扣除数。

> 有些资料会把年度速算扣除数除以 12，得到月度估算表里的速扣数。这个换算适用于粗略估算；本应用按年度累计应纳税所得额和年度预扣率表计算，并在每个月扣掉此前已预扣税额。

## 七、完整算一遍：月薪 20,000 元

假设：社保基数跟随工资、公积金比例 12%、工伤费率 0.2%、专项附加扣除输入 5,000 元；其他参数使用本应用默认值。

### 1. 个人每月缴费和税前扣除

| 个人缴费项目 | 算式 | 金额 |
| --- | --- | ---: |
| 养老保险 | 20,000 × 8% | 1,600 元 |
| 医疗保险 | 20,000 × 2% | 400 元 |
| 失业保险 | 20,000 × 0.5% | 100 元 |
| 住房公积金 | 20,000 × 12% | 2,400 元 |
| 大病统筹示例值 | 固定金额 | 3 元 |
| **个人扣款合计** |  | **4,503 元** |

### 2. 算出当月新增应纳税所得额

```text
20,000 - 4,503 - 5,000（基本减除费用） - 5,000（专项附加扣除）
= 5,497 元
```

### 3. 算出第 7 个月的预扣税

前 6 个月的累计应纳税所得额是 `5,497 × 6 = 32,982 元`，处于 3% 档，累计税额为 `32,982 × 3% = 989.46 元`。

第 7 个月累计应纳税所得额达到 `5,497 × 7 = 38,479 元`，进入 10% 档：

```text
截至第 7 个月累计应预扣税额
= 38,479 × 10% - 2,520
= 1,327.90 元

第 7 个月应预扣税额
= 1,327.90 - 前 6 个月已预扣的 989.46
= 338.44 元
```

第 7 个月进入 10% 档后，只有超过 36,000 元边界的累计部分按 10% 计算。扣税增加是累计收入跨档、追平累计税额的结果，并不是全部工资突然按 10% 征税。

### 4. 算现金到手和单位成本

```text
第 7 个月现金到手 = 20,000 - 4,503 - 338.44 = 15,158.56 元
```

单位每月缴费为 `20,000 × 26.5% + 20,000 × 12% = 7,700 元`，因此单位月总成本为 `20,000 + 7,700 = 27,700 元`。单位缴费不是从个人到手现金中再扣一次，而是单位在税前工资之外承担的成本。

在以上固定参数下，全年预扣个税为 `4,076.40 元`。实际结果可能因当地费率、社保基数上下限、实际专项附加扣除、入职月份、工资变化及年度汇算而不同。

## 八、页面里的“综合到手”和“综合到手 + 养老”是什么

为了比较现金工资以外的待遇，页面提供两个测算指标：

- **综合到手** = 税后工资 + 单位公积金 + 个人公积金 + 个人医保缴费金额。
- **综合到手 + 养老** = 综合到手 + 个人养老缴费金额。

这两个数是便于比较的模型指标，不是法定的“工资”或“个人资产”口径，也不代表全部金额都能立即支取。公积金和养老保险的实际账户归属、可提取条件及待遇，按当地现行政策和个人账户记录为准；个人失业保险、大病统筹和工伤缴费属于保障性扣缴，不计入这两个指标。
