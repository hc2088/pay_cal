## 3. 主要变化

| 维度 | 当前 App | V2 方案 |
| --- | --- | --- |
| 导航 | 单页方案、结果，附属历史和说明 | 测算 / 方案 / 工具三栏，结果和月度明细独立 |
| 收入 | 固定月薪 × 12 | 固定月薪 + 一笔全年一次性奖金，比较两种计税方式 |
| 地区 | 演示费率，没有城市 | 城市、人员类型、政策生效期；不支持地区可自定义 |
| 缴费 | 社保统一基数，多数比例固定 | 社保与公积金独立设置，个人/企业比例分列，各险种规则独立解析 |
| 扣除 | 月专项附加扣除合计 | 保留合计输入，新增个人养老金缴费计划与扣除时点 |
| 结果 | 多种综合收入口径同时出现 | 优先展示预扣后到账，单列税额、双边公积金、养老缴费、企业成本 |
| 历史 | 本地快照与删除 | 命名、复制测算、两方案对比，保留原始快照 |
| 技术 | 固定规则的单一引擎、SharedPreferences | 版本化规则、纯 Dart 计算模块、SQLite 快照事务 |

## 4. 版本范围建议

### V2.0：完成参考截图中的核心闭环

- 工资与年终奖测算、两种计税方式比较。
- 城市选择、按月解析规则、上下限说明、基数和比例调整。
- 月专项附加扣除、个人养老金输入。
- 年度结果、12 个月明细、计算过程、个人与企业缴费拆解。
- 本地方案保存、重命名、复制、删除；两个方案按年度、指定月份及个人/企业缴费逐项对比。
- 延续图片分享、离线规则说明，完成旧版设置与历史迁移。
- **全国城市配置属于 V2.0 核心范围**，已由用户明确；选择城市自动带入当地基数范围及双方比例，支持手动覆盖、单项与整体恢复。只有完成所选期间核验的模板才标注“已核验”，采集底稿不直接发布。

### V2.1：扩大使用场景

逐项专项附加扣除；年中调薪与入离职；三方案比较与更丰富导出。全国城市默认配置已纳入 V2.0，不再作为后续城市扩展功能。

### 后续独立规划

微信小程序、云同步、税后反推税前、劳务报酬、企业批量测算。截图只显示“更多计算”的入口，没有其内部截图，本轮不把猜测出的工具全部列入首发。

## 5. 产品决策摘要

1. **首页负责输入，结果页负责解释。** 用户点击“开始测算”生成结果，避免编辑一半时结果不断变化。
2. **首次默认带入北京参数。** 新安装默认选择北京，自动加载所选年度适用的基数范围、个人/单位比例及其他缴费配置；支持切换城市和手动调整。工资仍待填写，扣除和奖金默认为 0；已有用户恢复原草稿和参数，不被北京默认值覆盖。
3. **奖金比较显式呈现。** 默认进入“比较两种方式”，不悄悄替用户改变申报方式。
4. **城市规则按月份匹配。** 公积金年度可能跨自然年，不能把“2026 年”简单等同于一套全年费率。
5. **现金与账户缴费分开。** 公积金、基本养老个人缴费、个人养老金不混称为全部可支取的“税后总收入”。
6. **历史结果保持原样。** 新规则只在用户选择“复制并重算”后生效；旧版没有完整月明细时明确说明。
7. **首发不依赖后台。** 规则随版本发布，所有测算和历史在本机处理。
8. **城市默认与个人实际分开。** 切城市自动加载新模板，旧城市覆盖存为可恢复草稿；修改只影响当前方案。公积金默认预选当地标准范围上限，并明确这是可调整的测算假设。
