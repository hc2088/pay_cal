# 薪酬测算 V2 产品与交互设计

版本：0.4 评审稿 · 2026-11-09 · 首次默认带入北京参数 · 优先平台：Flutter iOS / Android

配套：[总览](00-改版总览.md) · [技术方案](02-Flutter技术实现方案.md) · [参考与验收](03-参考分析验收与实施计划.md)

## 1. 产品定位与目标

帮助个人回答四个问题：这份工资每月能到账多少；奖金按不同方式计税差多少；社保、公积金和公司成本分别是多少；两个 offer 在相同口径下差多少。

主要用户是求职比较薪酬的人、核对工资变化的在职员工，以及解释薪酬组成的 HR。默认场景为中国大陆居民个人、普通企业在职职工、同一纳税年度在同一单位任职 12 个月。

用户成功标准：首次使用能完成“填月薪、核对默认北京或切换城市、核对缴费、查看全年到账”；不需要先理解累计税率；查看任意月份能够解释从税前金额到到账金额的全部差额。

产品验证目标：在可用性走查中，首次完成基础测算不超过 90 秒；结果首页能直接找到到账、税额、个人缴费；从方案列表开始，进入比较模式、选择两份方案并确认不超过四次点击。以上是待验证目标，不是已有统计结果。

## 4. 核心用户流程

### 4.1 普通测算

首次打开测算并自动带入北京参数 → 填税前月薪 → 核对城市和年度（可切换）→ 核对基数/比例 → 按需填奖金和扣除 → 开始测算 → 查看年度结果 → 点击某月解释 → 保存或分享。

首页始终显示当前城市、政策覆盖状态和三项缴费摘要。高级配置收进二级页，但摘要可见。返回首页时保留草稿与滚动位置。

### 4.2 奖金决策

填写奖金和发放月份 → 确认是否符合全年一次性奖金条件、今年是否已使用单独计税 → 比较两种方式 → 展示各自年度税额及差额 → 用户选择查看的方式 → 对应结果与月明细同步。

“比较”不是第三种税制。用户未选择时，两张方案卡同时可见；系统可以标出“按当前输入，税额少 ¥X”，但不会替用户执行申报。零奖金时不显示无意义的比较卡。

### 4.3 Offer 比较

测算 A → 保存并命名 → 复制到新测算 → 修改工资/城市/奖金 → 保存 B → 方案列表选择 A、B → 查看到账、税、账户缴费、公司成本差额及输入差异。

不同城市允许比较；年度、收入范围、现金口径不同则提示差异并限制“高低结论”，见第 7 节。

### P02 城市与政策选择

搜索框支持中文、拼音全拼和首字母；其下是最近使用、已支持热门城市、按拼音分组的城市目录。右侧字母索引为辅助，搜索为主要路径。

每个城市带“已核验”“部分待补”“待核验”“暂无参数”状态。选择城市自动载入当地基数范围与双方比例；必要时补充医保档次或统筹区。缺少月份时明确指出，例如“2026 年 1–6 月规则待补充”。候选参考不能直接作为已核验模板；提供“使用自定义参数”。

首次默认选择北京，无需先进入城市页或申请定位权限。切换城市/年度先保存原作用域草稿，再自动加载新默认值；工资、奖金与扣除保持。旧城市手动参数不带入新城市，提供撤销切换；回到旧城市可主动恢复上次调整。普通切换不增加确认弹窗。完整规则见[全国城市配置方案](04-全国城市配置与自动带入方案.md)。

表内比例仅演示布局。正式模板显示政策值、可选范围、适用条件与日期。灰色“—”意味着本类别不向个人收取，不等于字段未知；“已含医疗”不能再重复加计。

“用当前月薪估算”是估算快捷方式，不宣称实际缴费基数每月必然随工资变化。已知缴费基数输入优先；超出区间时标准模式显示调整前后金额和原因。自定义模式允许复现工资单，但标明“用户参数”；超标准缴费不能自动全部作为税前扣除，需给出已确认的可扣除金额，否则只展示缴费测算、不生成税后结果。

社保与公积金的联动开关独立。保留“跟随社保参考值”便利选项，公积金仍按其自身限额处理。险种实际基数不同，显示逐项基数，而不是一行“社保基数”掩盖差异。

每个可编辑字段同时保留城市默认和我的值，修改后标记“已调整”，支持单项恢复。公积金在已核验范围内预选上限，明确标注“预选，按单位实际调整”；这不是全城统一实际比例。自定义高级页允许覆盖基数上下限，官方边界仍保留展示，税前扣除标准不随之自动修改。

“恢复本地区默认”重置本页费率、固定费用、基数模式及自定义边界，不重置工资、奖金与扣除。取消返回不提交该页草稿；存在未保存编辑时可选择保留编辑或放弃。用户覆盖按城市、年度、人员类型、档次和月份保存，不全局复用。

### P04 奖金与扣除

| 字段 | 默认 | 交互与校验 |
| --- | --- | --- |
| 全年一次性奖金 | 0 | ≥0、最多两位小数；普通季度奖等不作为本字段 |
| 发放月份 | 12 月，明确为默认假设 | 1–12 月；归属所选纳税年度，不跨年 |
| 比较方式 | 比较两种方式 | 也可直接选择单独/并入；不符合条件时只允许并入 |
| 单独计税资格 | 待确认 | 奖金 >0 时确认类型与本年是否已经使用；未确认不展示可直接采用的推荐 |
| 专项附加扣除 | 0 元/月 | 当前每月申报合计；不自动赠予 5,000 元示例值；信息入口说明适用范围 |
| 个人养老金计划 | 不缴纳 | 选择“每月等额”或“指定月份一次缴纳” |
| 每月养老金金额 | 0 | 当前规则下每月等额 0–1,000 元，全年不超过 12,000 元；这是等额计划限制，不是法律规定每月只能缴 1,000 元 |
| 一次缴纳金额及月份 | 0 / 12 月 | 全年 0–12,000 元，1–12 月；与每月等额互斥 |
| 养老金扣除时点 | 当年预扣时扣除 | 另可选“次年汇算扣除”；当年模式假定缴费当月提交有效凭证并被扣缴单位处理 |

个人养老金是自愿缴纳的独立资金账户，不是社保中的基本养老保险。年度限额与凭证要求依据[个人养老金税收公告](https://fgk.chinatax.gov.cn/zcfgk/c102416/c5237110/content.html)。页面把缴费金额、税前扣除、工资到账三者分开说明。

专项附加扣除首版只接收适用于每月预扣的合计，不把大病医疗等汇算项目平均塞入每月；信息页保留来源，逐项资格计算放在 V2.1。

### P06 月份列表与详情

列表默认四列：月份、工资及奖金到账、本月个税、详情。奖金月份带标记；税档变化月份给出短说明。固定表头与年度合计，允许大字体切换成卡片列表。

点击月份进入可滚动底部面板；内容较长或字体放大时使用全屏页。显示：

1. 当月工资、奖金、个人社保、公积金、固定扣费、工资税与奖金税、到账。
2. 每项个人/单位缴费及其基数、比例、舍入规则。
3. 累计收入、基本减除费用、可扣除缴费、专项附加扣除、个人养老金可扣除额。
4. 累计应税所得额 → 税率/速算扣除数 → 累计应纳税额 → 此前已预扣 → 本月预扣。
5. 当月所用城市政策、生效期和是否含自定义覆盖。

说明文案与数值均来自同一计算结果。累计应税所得不能写成“税后工资 × 月数”。

### P07 奖金方式比较

两列卡片分别展示单独计税与并入综合所得：工资相关税额、奖金单独税额（并入时为“已包含”）、年度总税额、年度税后收入、预扣后到账及可能汇算差额。

标题显示“在相同收入、缴费和扣除条件下”。只比较完整奖金在两种方式下的结果，不提供任意拆分奖金的所谓最优避税方案。选择方式后返回结果页；若规则年度超过已核验有效期，单独计税卡禁用并解释原因。现行公告执行到 2027-12-31，规则不能无条件延展至以后年度。[公告来源](https://www.mof.gov.cn/jrttts/202308/t20230828_3904461.htm)

### P08 方案列表与历史详情

默认按保存时间倒序，卡片显示名称、城市/年度、月薪/奖金、全年到账、保存时间、规则状态。时间以本地日期格式展示，例如“2026-11-06 09:25”，禁止把原始毫秒时间戳直接展示。

保存需点击按钮；自动保存的草稿不混入方案列表。首次保存名称建议“北京 · 月薪 33,000”，用户可改为“Offer A”。重复点击同次保存不得生成多份。编辑后再保存产生新快照；仅改名称可更新展示元数据。

详情只读。操作包括“复制并重算”“分享”“重命名”“删除”。复制保留原参数，新草稿提示采用原规则或当前规则及其影响；没有原始规则的旧记录只能保留原结果并要求核对新参数。

#### 差额与异常状态

移动端保持三列，差额放在 B 数值下方，例如“较 A +66.00”，避免四列挤压金额。差额为 B − A，单位随指标；只在有需要时展开百分比，A=0 时百分比显示“—”。相等行不重复展示零差额；数据缺失显示“未记录”，不是 0。

“只看差异”覆盖金额、输入和无法比较的项目：隐藏真正相等的值；保留缺失或口径不同的行及原因。全部相等时显示“当前可比项目无差异”，可关闭筛选看全表；仅公司成本不同则保留公司成本行及相关单位缴费入口，不能因现金相同就判定两方案相同。

企业成本更高使用中性差额，不解释成用户到手更高。选择不同年份、旧版指标或不同计算口径时仍能并排查看，但不输出误导性的数值差额或整体“更划算”结论。允许不同城市比较现金，同时展示城市及规则差异。

“年度汇总 / 月份明细 / 输入条件”为同页分区定位入口；纵向滚动时保留方案表头。普通字号采用统一行高约束的三列表格，避免两列独立滚动造成错行；大字体改为逐指标 A/B 成组卡片。返回列表保留已选方案，分享预览保留所选月份、列顺序和筛选范围，并标明“完整对比”或“仅差异”。

### P10 分享与 P11 工具/设置

分享先预览，提供年度摘要图与完整逐月图；比较图使用独立版式。内容包含输入摘要、城市/年度、规则状态、现金口径与生成时间。可隐藏方案名称、减少参数披露。由用户主动唤起系统分享或保存，不自动发送到任何联系人。

长图按内容长度控制尺寸，超出设备限制拆成摘要与明细两张；取消分享返回原页。生成失败可重试，不影响保存方案。分享按钮引用当前所查看的快照，不能误用首页草稿。

工具页复用奖金比较、缴费明细和规则组件；设置包含默认展示偏好、本地数据说明、清空方案、重置草稿、版本与隐私。清空方案与重置草稿分开，操作前展示数量并确认。用户明确清空全部本地薪酬数据时，连同迁移备份一起清除，避免重启后旧数据复活。

## 6. 字段、默认值与状态约定

| 项目 | 新安装 | 老用户升级 |
| --- | --- | --- |
| 城市 | 北京，自动选中；可切换 | 恢复已有城市；旧版无城市时仍为“旧版自定义参数”，不根据费率猜城市 |
| 年度 | 当前年；完整规则未覆盖时提示 | 旧记录年度未知；复制到新测算时由用户确认 |
| 工资 | 空，必填 | 保留既有工资 |
| 奖金 / 扣除 / 养老金 | 0 | 保留旧专项附加扣除，新增字段为 0 |
| 缴费 | 自动带入北京基数范围与双方比例；工资未填时实际估算基数待计算 | 保留原比例、基数模式和 3 元固定费示例，不伪装成新政策 |
| 结果 | 未计算 | 历史保持原样，当前草稿待重新计算 |

首次初始化和主动新建空白方案采用北京默认值；再次启动优先恢复原草稿，复制方案沿用原方案输入。“恢复本地区默认”始终恢复当前所选城市，不切回北京。默认北京不改变规则的核验状态，也不把当前月份的参数直接用于全年。

金额输入最多两位小数，支持粘贴后去除货币符号与千分位，再严格校验；空值与 0 区分。可选项空白在提交时明确归零，必填项空白报错。工资可为 0，但仍为全年任职假设，不等同于失业或无缴费。

为兼容旧数据，金额模型沿用原有整数上限；正常界面对超大金额提示核对，非法或溢出的输入不进入计算。费率受模板范围与档位约束；自定义百分数支持最多四位小数、0–100%，以 ppm 存储，保证 0.125% 等值无损；超出常见政策范围须显式标为自定义。

## 7. 统一金额口径

| 展示名称 | 定义 |
| --- | --- |
| 预计工资及奖金到账（预扣后） | 工资 + 奖金 − 个人强制缴费及固定扣费 − 本期工资税与奖金税 |
| 养老金投入后可用现金 | 上述到账 − 个人主动转入个人养老金账户的金额 |
| 年度应纳税估算 | 在本工具输入范围内计算的全年税负；不是已实际缴纳税额 |
| 预计汇算差额 | 综合所得已预扣 − 综合所得年度应纳税估算；正值表示可能退税，负值表示可能补税；奖金单独税不混入该余额 |
| 双边公积金 | 个人公积金 + 单位公积金，单列账户缴存 |
| 基本养老个人缴费 | 社保中的个人养老缴费，单列；不估算未来养老金 |
| 个人养老金缴费 | 用户本年自愿投入第三支柱账户的金额 |
| 企业用工成本 | 工资 + 奖金 + 单位缴费 + 单位固定费用；不再加一次个人扣款 |

年度主卡等于逐月到账求和。月均为年度值除以 12 的统计值，不参与税额计算。奖金比较使用相同的全年输入、规则、扣除和养老金安排，只改变奖金计税方式。旧记录缺少对应指标时显示“未记录”，不冒用其他口径填充。

## 8. 视觉与可访问性规范

建议方向：背景 `#F5F7FB`、卡片白色、主要文字 `#18263D`、主操作蓝 `#2458E8`、成功/较少税额使用深绿并附文字、异常使用深红并附原因。采用 8 点间距体系，页面边距 16，卡片内边距 16，卡片圆角 16，主要按钮高度至少 48。

数字与单位分层：主金额约 32–36 字号，标题 20，正文 16，辅助信息至少 12–14；金额右对齐、使用分组符和两位小数。政策时间与参数来源不只依赖颜色区分。点击热区至少 44×44 逻辑像素。

在 360 宽屏与 200% 字体缩放下走查；表格无法放下时改为卡片/横向可访问区，不能缩小到不可读。暗色模式可延后，但首发必须保证系统文字缩放和屏幕阅读器能读出金额、单位、选中状态及差额方向。

## 9. 范围变更处理

后续如果扩大到调薪、入离职或多单位，必须补齐累计月份、期初累计收入/扣除/已预扣、任职月份规则与年终汇算范围，再开放输入。领域模型预留逐月数据并不意味着产品已经支持全部税务场景。

全国默认配置是首发目标，城市目录、候选数据和正式规则分别跟踪。规则不足时如实显示待核验及缺口并保留自定义入口，不用未经核验的费率补齐正式支持数量；全国核验是独立发布依赖，不能把少量城市完成解释为全国功能完成。具体阶段与验收见配套文档及文档 04。
